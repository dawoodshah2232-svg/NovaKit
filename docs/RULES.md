# RULES — PDFEdit (NovaKit)

Coding standards for any agent working in this repo. **Repo reality wins over memory** — if a rule below conflicts with what the code does, update this file, don't argue with the code.

## Stack rules (owner, standing)

- Every project backend = **MySQL + PHP only** (cPanel hosting supports nothing else). No Supabase/Postgres backends for new work. (Current repo: frontend-only + Supabase analytics read; no new backend may be introduced.)
- **Pull before work:** `git fetch origin` + pull `main` before any change; never push from a stale copy. Never force-push. Never `git reset --hard` without explicit authorization.
- Typography: Apple font stack — `-apple-system, BlinkMacSystemFont, "SF Pro Display", "SF Pro Text", "Helvetica Neue", Helvetica, Arial, sans-serif`. Never Roboto/Titillium/Montserrat/Open Sans as primary. (Current layout loads Inter via `next/font` — see DESIGN.md; do not "fix" unilaterally.)
- **No emojis in UI.** Icons = Heroicons inline SVG only. (Current code uses `lucide-react` — compliance item, see TASKS.md.)
- Logos used raw, never on cards/boxes behind them.
- Load the apple-design + web-animations skills for any UI build/restyle.

## Conventions observed in this repo

- **Design tokens:** every shared-chrome/homepage component uses `--pe-*` CSS vars from `app/design-tokens.css` (`--pe-accent` etc.). No hardcoded theme-breaking colors; dark mode via `next-themes` class strategy + `.dark` overrides in the tokens file.
- **Honesty:** no fake stats, no invented features, no guaranteed outcomes. Success/empty states use real wording (see commits: "Honesty fixes", "flatten success wording"). Blog claims must match tool capabilities (e.g. one placement per SEO pass).
- **Blog content voice:** quotable headings, a "Q10 answer", full internal linking, human author voice; troubleshooting guides preferred. Never publish fake reviews, fake traffic claims, keyword stuffing.
- **Privacy-first code:** tools must work with analytics/ads blocked; analytics failures never escape into tool code (`try/catch`, `keepalive`, no-throw).
- **Security:** secrets stay server-only (no `NEXT_PUBLIC_` prefix on secrets); CSP allow-list stays minimal; admin routes password-gated; upload size guards on all tools (`lib/file-limits.ts`).
- **Next.js 16:** uses `proxy.ts` (not `middleware.ts`). The `<!-- BEGIN:nextjs-agent-rules -->` block in the repo `AGENTS.md` is auto-generated by `next dev` — leave it alone.
- **Commit style:** short imperative, scoped prefix — `docs: …`, `SEO: …`, `Fix …`, `AdSense: …`, `Daily content: …`. One concern per commit.
- **i18n:** root layout `<html lang="en">` is owned by another track — do not edit it; use `proxy.ts` for locale rewrites.

## What AI must do

- Inspect (branch, status, recent commits, this docs folder) before editing; test (`npm run build`, lint) after editing; `git diff --check` before commit.
- Update `docs/TASKS.md` and `docs/MEMORY.md` when work completes.
- Mark unknowns as TODO — never invent features, stats, or plans.

## What AI must NOT do

- Auto-deploy backend/payment code (standing deploy policy: backend batches need manual security review; frontend auto-deploy is fine).
- Touch `node_modules`, `.next`, `package-lock.json`, `tsconfig.tsbuildinfo` build artifacts.
- Re-verify or re-audit what a recent commit already covered (don't redo the SEO sweep; check the log first).
- Change AdSense/GA/analytics IDs without the owner's explicit instruction.
